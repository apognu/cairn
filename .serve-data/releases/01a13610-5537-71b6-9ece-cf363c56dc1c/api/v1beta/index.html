API / v1beta

v1beta

GET /cases

List cases

List cases according to a filter set. This endpoint will list all cases matching the filter, sorted by creation date, in the requested order. It will not reorder "waiting for action" or hide snoozed cases.

POST /cases

Create new case

Create a new case. This endpoint enforces the following preconditions: - All decisions exist and are not already assigned to a case

GET /cases/{caseId}

Get case

Get case by its ID.

PATCH /cases/{caseId}

Update case

Update a case. Some actions will be available through specific endpoints and will not be updateable from here.

GET /cases/{caseId}/ai_reviews

List AI case reviews

List AI reviews generated for the given case, ordered by creation date. The review content is not included, use the get AI review by ID endpoint to fetch the full content.

POST /cases/{caseId}/ai_reviews

Enqueue an AI case review

Create a new AI review for the given case, which will be processed asynchronously. Requires AI case review to be enabled for the organization Returns a 409 conflict if a review is already pending for this case.

GET /cases/{caseId}/ai_reviews/{aiReviewId}

Get AI case review

Get an AI case review by its ID. The full review content is included when the status is "completed".

POST /cases/{caseId}/close

Close case

Close a case with an optional outcome. This endpoint is idempotent and will result in a no-op if the case is already closed with the same outcome.

GET /cases/{caseId}/comments

List case comments

List comments that were left on the given case.

POST /cases/{caseId}/comments

Create new case comment

Write a new comment on the provided case.

POST /cases/{caseId}/escalate

Escalate case

Escalate a case, moving it to the configured escalation inbox and marking it as waiting for action. This endpoint enforces the following preconditions: - The source inbox is configured to have an escalation inbox

GET /cases/{caseId}/files

List case files

List files that were uploaded and attached to the provided case.

POST /cases/{caseId}/files

Upload case file

Upload a new file and attach it to an existing case.

GET /cases/{caseId}/files/{fileId}/download

Download a case file

Download the file that was uploaded on a case. This endpoint will provide a temporary download URL for the file that can be retrieved in two ways, depending on the capabilities and configuration of your HTTP client: - It will be included in the response body - It will be part of a redirect status flow in the response

POST /cases/{caseId}/reopen

Reopen a closed case

Reopen a closed case. This endpoint is idempotent and will result in a no-op if the case is still open.

POST /cases/{caseId}/tags

Add tags to a case

Add one or more tags to a case. This operation is idempotent: adding a tag that is already present on the case is a no-op. All provided tag IDs must reference tags with `target=case`. Returns 400 if any tag has a different target.

DELETE /cases/{caseId}/tags/{tagId}

Remove a tag from a case

Remove a tag from a case. This operation is idempotent: removing a tag that is not present on the case is a no-op.

POST /continuous-screenings/objects

Add an object under continuous screening with given configuration

This endpoint is idempotent. If the object is already under monitoring, the call succeeds and re-runs the screening, returning the latest result. It is safe to retry this call to retrieve an up-to-date screening result.

DELETE /continuous-screenings/objects

Remove an object from continuous screening

POST /decisions/async

Create a batch of async decision executions

Enqueue multiple asynchronous decision executions at once. When `ingest` is true, the object will be ingested before decisions are created. Note that this endpoint is not compatible with optional side effects of ingestion, such as addition to continuous screening (though if the record is already being monitored, it will trigger a new screening with the updated data). GET /decisions/async/{executionId}

Get async decision execution status

Retrieve the current status and details of an async decision execution. Old executions are kept for 30 days after completion, so the endpoint may return a 404 status for old executions that have been deleted.

GET /ingest/{objectType}/uploads

List batch ingestion logs

PUT /ingest/{objectType}/uploads

Upload a CSV file that will be ingested asynchronously

This endpoint will emit a presigned URL to which to upload the file. The actual upload must start within one minute of the initial call, and terminate within 15 minutes. The HTTP client used **must** then replay the request to the provided URL with the same headers as the initial request except for the Marble API key, and upload the CSV file. DELETE /records/annotations

Delete annotations by ID

Delete one or more annotations by their IDs. This operation is idempotent — IDs that do not exist are silently ignored. All deletions are performed atomically.

GET /records/annotations/{id}/files/{partId}/download

Download a file annotation part

Download a specific file within a file annotation.

GET /records/{recordType}/{recordId}/annotations

List annotations for an record

List all annotations attached to a specific record.

POST /records/{recordType}/{recordId}/annotations

Attach annotations to an record

Attach one or more annotations to a specific record. Supported annotation types are `comment`, `tag` and `risk_tag`. For `tag` and `risk_tag` types, if an identical annotation already exists on the record, the existing annotation is returned instead of creating a duplicate. To attach a file annotation, use the dedicated endpoint `POST /records/{recordType}/{recordId}/annotations/files`.

POST /records/{recordType}/{recordId}/annotations/files

Attach files to a record as an annotation

Upload one or more files and attach them as a file annotation to a specific record.

GET /risk-levels/{objectType}/{objectId}

Retrieve a record's active risk level

POST /risk-levels/{objectType}/{objectId}

Override a record's risk level

GET /tags

List tags

List all tags for the organization. Tags can be filtered by target type using the optional `target` query parameter.
